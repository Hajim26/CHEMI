# CHEMI (케미) — AI 기반 공모전 팀원 추천 MVP

**최신 소스: 시연용 매칭 요청 지원 (Step 22).** 대학생의 경험을 AI 인터뷰로 분석하고, 강원대학교 공모안내와 연결하여 역량 상호보완형 팀원을 추천하는 웹앱입니다.

## 바로 실행하기 (Windows)

1. Python 3을 설치합니다.
2. `.env.example`을 참고하여 프로젝트 루트에 별도 `.env` 파일을 생성하고 **본인의** OpenAI API 키와 Supabase Project URL 및 Publishable Key를 입력합니다. `.env`는 GitHub에 올리지 않습니다.
3. Supabase 프로젝트의 `database_setup.sql`, `matching_migration.sql`이 이미 적용됐다면 다시 실행할 필요가 없습니다. 신규 프로젝트는 [SETUP_STEP11.md](SETUP_STEP11.md)의 순서와 정책을 검토합니다.
4. `RUN_CHEMI_WINDOWS.bat`을 실행하고 `http://127.0.0.1:8000/`에 접속합니다.
5. 테스트: `RUN_STEP21_TESTS_WINDOWS.bat` (Python 3 및 선택적으로 Node.js 사용).

## MVP 범위와 시연 주의사항

- 기능: 회원가입/로그인(Supabase Auth), AI 경험 인터뷰 및 핵심역량 저장, 강원대학교 공모안내 수집/정렬, 팀원 추천/상세보기, 매칭 요청.
- **가상 팀원 100명**은 `data/`에 보존된 합성 데이터이며 **실제 가입자 아님**. 가상 팀원에게 보내는 요청은 브라우저의 시연 기록으로만 저장되며 상대방에게 전송되지 않습니다.
- 실제 회원끼리의 매칭 요청은 참여 동의와 인증이 필요합니다. 요청 수락/거절 코드는 있으나 실제 Supabase 계정 간 통합 검증은 별도 필요합니다. 팀 생성과 채팅은 향후 고도화 범위입니다.
- 궁합점수는 제한된 공개 정보에 기반한 **예비 점수**로 협업 성공률을 의미하지 않습니다. 모집 마감일/자격요건을 검증한 최종 지원 가능 목록이 아닙니다.
- 공개 배포 전: Supabase 이메일 인증, RLS, 탈퇴 처리, 호스팅 보안 설정과 API 사용량 제한 등을 반드시 검토해야 합니다.

# CHEMI 19단계 — 팀원 매칭 요청 버튼 + 역할 보완 추천 고도화

**17·18단계(팀 확정/채팅)는 구현하지 않았습니다.** 이번 변경은 16단계 버전을 기반으로 합니다.

## 핵심 변경

1. 공모전 1순위 팀원 카드에 **[팀원 상세 보기 ↗] [매칭 요청]** 버튼을 나란히 표시합니다.
   - Supabase의 매칭 참여에 동의한 실제 회원: **매칭 요청** 클릭 → 확인창 → `POST /api/team/request` → **응답 대기**. 상대는 기존 요청 목록에서 수락/거절할 수 있습니다.
   - 가상 100명: **매칭 요청** 버튼은 표시하되 비활성화, 실제 DB에는 요청을 저장하지 않습니다.
   - 보낸 요청 이력에 있으면 중복 신청을 차단하고 상태를 표시합니다.
2. 기존 `matchmaking.py`의 4개 광범위 분야 대신 구체 역할(개발, 데이터/AI, UI/디자인, 서비스 기획, 발표/홍보, 현장/정책, 환경/에너지, IoT/하드웨어)을 비교합니다.
3. 부족한 역할을 채워 주는 후보를 우선하고, 공모전 제목·분야의 관련성 및 관심 분야를 분리해 점수화합니다.
4. 팀원 상세 화면에서 요소별 **예비 점수 내역**을 확인할 수 있습니다.
5. OpenAI는 사전 선별된 상위 16명의 후보 중 1명을 선택하고 추천 이유를 작성할 수 있습니다. **숫자 점수는 정해진 산식으로만 계산**되어 AI가 임의로 높은 점수를 반환해도 채택되지 않습니다.

## 추천 산식 (가중치 합계 100)

| 항목 | 최대점 | 구현 방식 |
| --- | ---: | --- |
| 부족 역할 보완 | 35 | 제목·분야에서 추론한 역할 중 사용자가 아직 갖추지 못한 역할을 후보가 얼마나 채우는지 |

## 기존 10단계에서 유지된 기능


## 이번 버전에서 추가된 기능

- 기존 10명(`TM001~TM010`)의 데이터는 그대로 유지하고, 새로 합성한 **90명(`TM011~TM100`)**을 추가했습니다.
- SQLite `data/teammates.db`의 **총 100명 / 핵심역량 300개 / 관심분야 236개**를 활용합니다.
- 개발·AI, 데이터, UX/디자인, 콘텐츠, 기획, 발표, 지역·사회, 에너지·공학, 융합 등으로 가상 전공/역량을 확장했습니다.
- `data/teammates_100.csv` / `data/teammates_demo.json`에서 전원 확인 가능합니다. 신규 90명만 보려면 `data/teammates_extra_90.json` 또는 `data/teammates_extra_90.csv`를 이용하세요.
- 기존 궁합점수 계산식은 유지합니다. **100명 전체 규칙 평가 → 공모전별 상위 16명 AI 평가 → 1순위 추천** 구조입니다. 매칭 상세 설명은 `MATCHING_LOGIC.md`에 있습니다.
- 테스트할 때만 사용하는 **합성 데이터**이며, 실제 회원 100명이 가입했거나 연락할 수 있다는 의미가 아닙니다.
- **실제 Supabase `chemi_profiles`/`chemi_analyses`에 가상 인물을 업로드하지 않습니다.** 이 DB는 로컬 시연용 SQLite와 분리되어 있습니다.

이번 버전은 기존 8단계 **AI 경험 인터뷰 → 핵심역량 → 공모전 → 가상 팀원 추천** 기능을 유지하고 다음을 추가했습니다.

- 실제 이메일/비밀번호 회원가입 및 로그인 (Supabase Auth)
- 내 계정에 닉네임, 대학, 학과, 학년을 저장 (Supabase PostgreSQL)
- 개인정보 및 분석 결과의 온라인 저장에 대한 동의 체크
- AI 핵심역량 분석 성공 시 **경험 원문 + 1~2회 인터뷰 답변 + 역량 이름/근거/수준** DB 저장
- 다시 로그인할 때 최신 분석 결과 불러오기, 프로필 수정, 저장 데이터 삭제, 로그아웃
- RLS: 사용자 A는 사용자 B의 프로필/분석 기록을 직접 읽거나 수정할 수 없음

⚠️ **실제 Supabase 서비스에 자동으로 가입하거나 프로젝트를 생성하는 기능은 없습니다.** 프로젝트 생성, SQL 실행 및 `.env` 값 입력이 필요합니다. Supabase가 미설정일 때는 이전과 같은 **로컬 시연 모드(온라인 미저장)** 로 작동합니다.

## A. Supabase 생성하기 (기존 프로젝트가 있다면 건너뛰기)

1. https://supabase.com/dashboard 에 접속해 새 프로젝트를 생성합니다.
2. 왼쪽 **SQL Editor → New query**에서 `database_setup.sql`의 전체 SQL을 붙여넣어 **Run** 합니다.
3. **Project Settings → API Keys** 또는 **Connect**에서 프로젝트 URL과 **Publishable key (`sb_publishable_...`)**를 확인합니다. `sb_secret_...` 또는 `service_role` 키는 사용하면 안 됩니다.
4. **Authentication → Providers → Email**에서 이메일/비밀번호 로그인을 사용 가능한지 확인합니다.
5. 이메일 확인(Confirm email)이 활성화된 경우 **Authentication → URL Configuration**의 **Site URL**을 로컬 테스트 주소 `http://127.0.0.1:8000/`로 설정합니다. 공개 배포 후에는 실제 HTTPS 도메인으로 바꿉니다. 회원가입 후 받은 이메일 인증 링크를 클릭해야 로그인됩니다.

## C. Windows 실행

1. `RUN_CHEMI_WINDOWS.bat`을 더블클릭합니다. 별도 Python pip 설치는 필요하지 않습니다.
2. 주소창에 `http://127.0.0.1:8000/`을 직접 입력합니다.
3. 화면의 **회원가입**으로 이메일/비밀번호를 등록합니다. 인증 메일이 요구되면 인증 후 로그인합니다.
4. 개인정보 입력 → 저장·활용 동의 → **기본 정보 저장하고 다음으로** 클릭합니다.
5. 기존처럼 경험·활동을 적고 AI 꼬리질문에 답변합니다. 최종 분석이 성공하면 자동으로 **본인 계정 DB에 저장**됩니다.
6. 로그아웃 후 동일 계정으로 다시 로그인하면 **저장된 내 핵심역량 다시 보기** 버튼이 나타납니다.
7. 새로 만든 **다른 계정**으로 로그인하면 이전 계정 정보가 보이면 안 됩니다.

## D. 데이터 테이블 / 데이터 공개 범위

| 저장 위치 | 데이터 | 조회 가능한 주체 |
|---|---|---|
| Supabase Auth `auth.users` | 이메일, 비밀번호 인증 정보 | Supabase Auth 관리 |
| `public.chemi_profiles` | user_id, 닉네임, 대학교, 전공, 학년, 동의시각 | **로그인한 본인만** (RLS) |
| `public.chemi_analyses` | 사용자 원문 경험·답변, AI 핵심역량·근거·수준 | **로그인한 본인만** (RLS) |
| `data/teammates.db` (기존) | 가상 학생 100명 시연용 데이터 | 시연용 가상 추천에 사용 |

`database_setup.sql`은 테이블 생성, 권한 최소화, RLS의 본인만 SELECT/INSERT/UPDATE/DELETE를 시행합니다. **실제 회원끼리 공개 매칭하는 API는 `matching_migration.sql` 실행과 명시적 참여 동의 후에만 동작합니다.** 동의 없는 공개 매칭을 방지하기 위해 매칭용 `chemi_match_profiles`, `chemi_match_requests` 테이블과 RLS/RPC 정책은 신규 SQL에 포함되어 있습니다.

## E. API 구조

- `POST /api/auth/signup`: 계정 생성. 인증 메일이 필요한 경우 바로 로그인되지 않을 수 있습니다.
- `POST /api/auth/login`: 로그인. **HttpOnly SameSite 쿠키**로 로그인 세션을 유지합니다.
- `GET /api/auth/me`: 로그인 상태와 내 프로필·핵심역량 복원
- `POST /api/auth/logout`: 로그아웃, 쿠키 삭제
- `PUT /api/me/profile`: 동의 후 기본 프로필 DB에 저장
- `GET /api/me/analysis`: 내 최신 AI 분석 결과 조회
- `DELETE /api/me/data`: 내 프로필과 분석 기록 삭제. **로그인 계정 자체는 남습니다.**
- 기존 AI 경험 인터뷰, 공모전 크롤러, 가상 팀원 추천 API 유지

OpenAI API 요청에 기본 프로필(이름, 계정 이메일, 전공)은 포함하지 않고 경험과 인터뷰 답변만 전송합니다. 그러나 경험에 포함한 이름/연락처 등은 텍스트의 일부로 전송될 수 있으므로 민감정보를 적지 않도록 안내하세요. **AI 분석은 공식 능력 검증이 아닌 추정**입니다.

## F. 공개 배포 전에 해야 할 일

현재 Windows 로컬에서 로그인과 DB 저장 구조를 시험하기 위한 개발 버전입니다. 여러 사용자가 인터넷에서 접속하려면 HTTPS 기반 Python 서버 호스팅, 정식 이용약관·개인정보 처리방침과 보관기간, 회원 탈퇴 및 계정 삭제 절차, 모델 사용량/요금 제한, 가입 및 AI API 요청 속도 제한, SMTP 이메일 발송 설정, RLS 통합 검증, 보안 점검이 더 필요합니다.

서버가 실제 호스팅될 경우 `CHEMI_HOST=0.0.0.0`, `CHEMI_ALLOWED_ORIGIN=https://실제도메인`, `CHEMI_COOKIE_SECURE=1` 환경변수를 설정하고, 호스팅 서비스의 `PORT` 환경변수를 사용하도록 구성되어 있습니다. **HTTPS와 Rate Limit을 설정하기 전에 공개적으로 배포하지 마세요.**
